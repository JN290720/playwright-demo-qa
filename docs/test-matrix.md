# テスト観点表（画面 × 観点）

「何を、どこまでテストしているか」と、その抜けを一覧にしたものです。優先度付けの根拠として使います。
更新のしかた: テストを追加・削除したら、このファイルも同じ PR で更新してください。

- 対象: SauceDemo（`https://www.saucedemo.com`）に対するテスト
- 凡例: ✅ あり / △ 一部のみ / ❌ なし / ─ 対象外
- 括弧内は、対応する spec とケース番号、または抜けを扱う Issue です（`#` は `playwright-demo-qa` の Issue）

補足:
- VRT は、`desktop-chrome` / `mobile-chrome` / `desktop-safari` の 3 プロジェクト × 8 画面 = 24 枚のベースライン（`*-linux.png`）がある。関数名の「(PC)」は名前だけで、モバイルのプロジェクトでも実行される
- **実行環境（#45）**: stg（PR の CI）は**全テスト**、prd（Post-Deploy）は **`@prd` タグ付きの必須の主要機能のみ**。`@prd` の対象: 購入フロー E2E、ログイン・カート追加、TodoMVC の基本機能。a11y / VRT / network / security / API / ソート・カート / 購入入力の検証 / 破壊的・異常系は、stg のみ
- SauceDemo 以外の対象（TodoMVC、`playwright.dev`、jsonplaceholder）は、デモ用として、この表の対象外（`demo-*.spec.ts`、`example.spec.ts`、`api-demo.spec.ts`、`saucedemo-basic.spec.ts` ※名前と中身が不一致。#17）

## 3. 品質上の注意（観点とは別）

- 認証情報・URL がテストに直書き（約 27 か所・14 か所）→ #18 / #41
- ログイン手順が a11y / VRT / network の各 spec に重複 → POM に寄せる（`CLAUDE.md` の規約）
- `retries: 2` により、不安定なテストが「成功」に見えて気づけない → #37
- a11y の除外・既知の不備は、`docs/a11y-known-issues.md` に台帳として記録（`select-name` の除外、カートのリンクがキーボードで開けない不備など）。失敗を期待するテスト（`test.fail()`）は、サイトが直ると失敗して気づける（#58）

## 4. 重視する観点（判断待ち）

優先順位の案: **機能（購入フロー・金額）→ セキュリティ（認可・セッション）→ a11y → 性能（今回は対象外）**。
ユーザーの判断で変わります（#39）。
